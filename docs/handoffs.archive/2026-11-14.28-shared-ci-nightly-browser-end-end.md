## Handoff

Done in statewalker/.github#8 (squash-merged as 5df730f).

- **Reusable workflow:** `statewalker/.github/.github/workflows/nightly.yml@main` (`workflow_call`).
  - **Opting in:** a project adds its own scheduled workflow calling it, with `permissions: issues: write`. The snippet is in the `.github` README, section "Nightly browser and end-to-end suites".
  - **The script a project provides:** a root `test:nightly` that runs every browser and end-to-end suite, for example `pnpm -r --if-present run test:browser && pnpm -r --if-present run test:e2e`. It runs after the install, `build` and the `setup` input (browsers).
  - **Inputs:** `test-command`, `node-version`, `timeout-minutes` (default 90, so a hung suite fails and is reported instead of being cancelled at the 6-hour limit), `checks-ref`.
- **On failure** (of the suites, or of the install/build before them), `scripts/report-nightly.mjs` opens one issue in the project, "Nightly: browser and end-to-end suites fail", labelled `bug` + `ci-baseline` (the labels are created if missing), linking the run. While it is open, later failures comment on it (the duplicate check). A passing or cancelled run writes nothing. The run itself fails, so it shows red.
- **Tests:** `tests/report-nightly.test.mjs` runs the reporter against a local stand-in for the GitHub REST API, seeded from recorded responses (`fixtures/nightly/`). It covers: one issue opened, a second failure updating it, nothing written on success or cancel, unrelated `ci-baseline` issues and same-titled pull requests ignored, an API error failing.
- **Pilot:** none yet. A failing pilot would open real issues; the first project to opt in during statewalker/statewalker-root#29 is the pilot.
