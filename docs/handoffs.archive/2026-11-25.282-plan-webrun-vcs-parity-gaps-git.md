### The loop that worked (keep 4–6 PRs open)
1. **Claim** the root ticket: assign it to the human and post the claim comment.
2. **Set up a worktree:** `git worktree add -b claude/<n>-<slug> /home/user/webrun-vcs-<n> origin/main`. Then run `pnpm install --frozen-lockfile && pnpm -r build` and push the branch.
3. **Implementation agent:** writes tests first; uses native-twin tests against git 2.43 (system) and 2.56.1 (`<scratchpad>/git2561/bin`, no curl, so its HTTP twins fail there for environmental reasons; source in `<scratchpad>/g2561`); adds a changeset; merges the branch, then origin/main, and pushes. It does not open the PR.
4. **Open the PR** (MCP `create_pull_request`; body has Changes + Test plan + attribution), then `subscribe_pr_activity`.
5. **Gate reviewer agent:** works in a fresh `git worktree add --detach <scratchpad>/rNNN <sha>`, never `cp -a`; never prunes, never stashes, never `rm -rf` outside its own directory. Reports criticals, plus highs in the changed lines, with native-git repros.
6. **Post one record comment per pass**, ending `<!-- gate: pass=n critical=… -->`. Send fixes back to the same implementation agent. Re-verify only the fix diff. At most 3 passes for criticals; a high gets fixed if cheap, otherwise filed as a follow-up.
7. **Merge:** squash with `expectedHeadSha` set to CI's "chore: record tested packages" commit, once its quick `ci / ci` is green. Then:
   - comment "Done: … (squash X)" on the root ticket and close it as completed;
   - remove the worktree with `git worktree remove --force`;
   - merge main into the other open branches: fetch the branch and merge `FETCH_HEAD`, then separately fetch and merge `origin/main`. Never fetch two refs at once, which would start an octopus merge.

**Gotchas seen in this wave:**
- Every merge to main makes the other PRs dirty, through `.tested` conflicts.
- Notifications often carry a stale head SHA. Always re-read `pulls/N` before acting.
- If an agent is still editing the worktree, don't merge into it; tell the agent instead.
- Conflict resolutions that change code need their own gate pass.
- **Release:** after a wave, gate the open `chore: version packages` PR (branch `changeset-release/main`) and merge it. CI publishes. Never publish by hand.
