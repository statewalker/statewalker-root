**Code execution, decided.** [How is the external executor pool built?](https://github.com/statewalker/statewalker-root/issues/400) is closed. Its resolution comment plus **two amendments** (2026-11-24 and 2026-11-25) hold the decision; read all three. In short:

- There is no bespoke pool. There are two code-executor kinds, and both take one init, `capabilities: { files, fetch, rpc }` plus `cwd`, engine or image, `env` and `limits`. Nothing is ambient: the integration's capability objects carry the policy.
- **Light container** (`ctx.lightContainer`) is the default for `python` and `node` scripts on cellb, celld and workerd. Its engines are CPython for WASI and QuickJS in Worker Loader isolates, plus Pyodide on cellb. It ships as `@statewalker/webrun-light-container` in a new layer-0 monorepo, `webrun-capabilities`, beside `webrun-biscuit`.
- **Container** (`ctx.container`) is for what a light container can't run: native packages, `npm`, servers. There is one per agent session in a container DO, with no credential inside. The first engines on cellb are Lifo (trusted runs only) and a WASI engine. Wasmer waits on upstream (see "Waiting on the human").
- The `engine` and `pool` kinds are gone. The order: light container everywhere, then container on cellb, then Workers, then celld.

## The upstream Wasmer pull request (prepared, not opened)

cellb-containers' Wasmer engine depends on a local pnpm patch of `@wasmer/sdk` 0.19.1, and a patch doesn't travel with a published package. The upstream change exposes what the SDK's core already has:
- `mounts` and `storage`: each guest filesystem call goes to the embedder, which can refuse it with `EACCES`;
- the host-filesystem bridge in Node workers;
- `Ports.fetch`/`connect`;
- a `@wasmer/sdk/host-filesystem` export.

Its description gives the reason and use case: access control on file and network calls for untrusted agent code.

- **Commit:** [`embedder-mounts-and-port-streams.patch`](../upstream/wasmer-sdk/embedder-mounts-and-port-streams.patch), on top of wasmerio/wasmer-sdk `main` at `ddbd6cd`.
- **Pull-request description:** [`embedder-mounts-and-port-streams.pr.md`](../upstream/wasmer-sdk/embedder-mounts-and-port-streams.pr.md).
- **Tested:** I applied it to the `wasmer-sdk-js-v0.19.1` tag and ran it with the published 0.19.1 wasm. The 4 new tests pass, and the existing `host-filesystem` (6) and `validation` (7) tests still pass. On `main` it typechecks; the wasm core can't be built in a cloud container, so the full suite is left to upstream CI.
- **To open it, once `statewalker/wasmer-sdk` exists:**
  1. Attach the fork with push access.
  2. Clone it and `git checkout -b js-embedder-mounts-and-port-streams ddbd6cd`, deepening the clone if needed.
  3. `git am` the patch and push.
  4. Open the pull request against `wasmerio/wasmer-sdk:main` with the description file. This session's GitHub access covers only statewalker repositories, so if opening it on wasmerio is refused, give the human the compare link.
  5. Afterwards, link the pull request from #423 and in cellb-containers' README.
