- **`secret-scan: true`**: gitleaks 8.30.1, pinned by SHA-256 in `scripts/install-gitleaks.sh`, scans right after the checkout and before the install.
  - **What it scans:** the checked-out files, and every commit from the pull request's base (`github.event.pull_request.base.sha`; on a push, `before`). So a secret added and deleted again within a pull request fails too. The switch checks out with `fetch-depth: 0`.
  - **Output:** findings are redacted.
  - **False positives:** go in the project's `.gitleaks.toml` or `.gitleaksignore`.
- **`release-path: true`**: `scripts/check-release-path.mjs` fails any publish step outside the job `publish` of `.github/workflows/ci.yml`. That covers other jobs, other workflow files and composite actions. A publish step is any of:
  - `npm`/`pnpm`/`yarn`/`bun publish`, `yarn npm publish` or `changeset publish`, in any position in a command;
  - a root script that reaches one of these;
  - `changesets/action` with `publish`;
  - an npm-publish action.

  `--dry-run` does not count. It passes on the current workflows of kernel, webrun-files, httpeers, webrun-wire, cellb.dev, knowledge and webrun-sites.
