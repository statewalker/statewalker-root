# Handoff: Kitesurf on CellB (Node and a browser tab)

No ticket: a session started from the human's request to run
[Kitesurf](https://github.com/cloudflare/kitesurf) on CellB. Kitesurf is Cloudflare's experimental
browser engine, packaged as a Worker (Rust and wasm) and driven over the Chrome DevTools Protocol
(CDP).

## Done

- **Kitesurf runs unchanged on CellB**, in Node and in a Chromium tab. The host app is
  `statewalker-sandbox/apps/kitesurf-cellb` (README there):
  - In Node, it serves the CDP endpoint at `ws://127.0.0.1:8787/devtools/browser` for Puppeteer
    and other clients.
  - In a tab (`browser/`), the engine runs in a Dedicated Worker, and each page Kitesurf opens in
    a Dedicated Worker of its own. The page drives the engine over CDP through a `MessagePort`.
  - Checked: example.com, Hacker News and the React and Vue TodoMVC apps render, take input, and
    give screenshots. A page load takes about 1.5–3 s.
- **PDF output** comes from CDP `Page.printToPDF`. In Node, use `PDF=<file> node smoke.mjs <url>`;
  in a tab, use `node run.mjs <url> 8800 --pdf`. A sample page is at `browser/demo/report.html`.

## For the next session

- **Building Kitesurf** takes Bazel and Rust, about 13 minutes on 4 CPUs. Where GitHub archive
  downloads are blocked, override the `bats` toolchain with npm's `bats@1.10.0`; the app's README
  gives the flags.
- **In a tab, page fetches go through a CORS proxy** (`browser/serve.mjs`, `/proxy`). The browser
  drops `Set-Cookie` and forbidden request headers such as `User-Agent`. CDP clients outside the
  tab cannot reach the engine.
- **A failed `Page.printToPDF`** answers with an `error` field beside empty `data`, not with a CDP
  error. Check that field.
- **CellB does not enforce per-isolate `limits`** (CPU time, subrequests), so a runaway page
  script is not stopped. It also does not enforce `global_fetch_strictly_public`.
- **Load** `tdd` for CellB changes.
