## Decisions the human made

**Round 1, Q1 to Q5: "yes to all five".**
- Q1. The wedge is (a): the agent-assisted, in-browser workspace for Cloudflare Workers, Durable
  Objects, Astro/EmDash and Flue apps, built from `cellb.dev/apps/sandbox` and `sandbox-hub`.
  This answer was later superseded; see Q11.
- Q2. Traction first: a generous free tier, charging only for hosted cost, aiming for weekly
  active projects.
- Q3. The product complements Cloudflare. It deploys to the user's own Cloudflare account and
  does not compete on hosting.
- Q4. The product is a glossary **Application** with a placeholder name until #198. "Sandbox"
  keeps its glossary meaning.
- Q5. The product leads development for the next 3 to 4 months. The maps (#112, #111) order their
  work by what it needs.

**With that answer, the human added:**
- PeerShare moves to <https://github.com/sandclaw-ai>.
- "StateWalker ecosystem contains technological blocks and SandClaw contains branded
  applications, assembled on top of the platform."

**Round 2, Q6 to Q10.** The session proposed these from that statement:
- Q6: SandClaw-branded applications in `sandclaw-ai`.
- Q7: Cloudflare-stack developers first.
- Q8: a value-proposition sentence.
- Q9: an ADR plus glossary edits.
- Q10: PeerShare out of scope.

The human answered with a new model instead, which replaces them. Q10 no longer applies.

**The model the human gave (2026-11-21, quoted in substance):**
- **SandClaw** is the open-source application layer, built on the StateWalker technology blocks:
  the agentic platform on CellB, VCS, HTTPeers and the others.
- **Money** comes from two sources:
  - hosting pre-configured, domain-specific services: S3 buckets (RustFS or AWS S3), git servers
    (Gitea, GitLab), HTTPeers relays and hubs, AI model access, OpenTelemetry dashboards, and user
    management (OAuth, OpenID);
  - packaging the same stack for on-premise installation.
- **Visibility** comes from thematic sites:
  1. the building blocks (VCS, HTTPeers, CellB, the platform);
  2. third-party applications running local-first in the browser, with a path to a server or the
     cloud (EmDash, Astro, Observable Framework);
  3. custom browser prototypes: office-document versioning, PDF scanners and generators, a code
     studio, LLM chat, an indexer and search, a wiki. Most of these already exist.
- **Promotion:** a block or app that draws a positive, measurable reaction from developers is
  developed in open source and packaged as a commercial offer through SandClaw.
